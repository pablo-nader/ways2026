### Key Accomplishments

1. **`articulos` (tenant-wide, not `id_empresa`-scoped)**:
   - Full field set: clasificadores (area, categoria, marca, grupo), alicuota_iva, unidad_venta, costs, es_producto
   - Availability model: `disponible_para_todas` (default true) auto-covers future empresas; `articulos_empresas` junction for explicit subsets
   - Autogenerated `codigo_interno` per tenant (atomic counter), with user-supplied value support
   - Full CRUD + barcode manager inline
   - Test coverage: RLS proofs, availability rules, concurrent autogeneration

2. **`codigos_barra` (N per artículo, tenant-unique)**:
   - Uniqueness constraint: `(codigo, id_tenant)` — one barcode per tenant per artículo, no per-artículo overrides
   - Add/remove/list management independent of artículo edits
   - Race test: concurrent duplicate barcodes → exactly 1×201 + 1×409
   - GET endpoint added mid-slice by judgment-day demand

3. **`precios` (history engine with close-and-open semantics)**:
   - Price changes never UPDATE a row; instead close the vigente row and open a new one
   - Point-in-time query by date resolves historical prices correctly
   - Programmable future prices: at most ONE pending per `(articulo, lista)` pair
   - Derived-list resolution at read time: `precio_base * (1 ± porcentaje)`, no stored rows for derived lists
   - Advisory lock (pg_advisory_xact_lock per pair) serializes concurrent writes
   - 4 judgment-day rounds; multiple CRITICAL findings fixed (predecessor re-close, interval validation, dead-row exclusion, timestamp capture)

4. **`listas_precio` ABM (completed from stage 2's "minimal")**:
   - Both `fija` and `derivada` modes now functional
   - Full create/edit for tenant admins
   - Mode-switch blocked once precios history exists
   - Deactivation blocked while active derivada lists depend on it as base
   - `EsDefault` SWAP semantics: atomically demarcate old default in the scope, mark new default
   - Protected-default-row guards: edit/deactivate/delete all blocked without same-request replacement
   - Generic `MapearCatalogo<>` helper reused; no dedicated endpoints file

5. **Margin-based price suggestion**:
   - Pure domain function: `SugeridorDePrecio.Sugerir`
   - Precedence: `grupos.margen` (group) > `proveedores.margen` (supplier) fallback
   - Base cost: `costo_nominal` > `costo_lista * (1 - descuento_proveedor)`
   - **Never auto-applied** — always click-to-apply in the UI

6. **Web screens**:
   - **Artículos screen** (heaviest to date, ~1.6k lines front-end):
     - Identification + inline barcode manager + classification (4 selectors) + costs + availability picker (toggle + empresa multiselect)
     - Per-lista price editor with history drawer
     - 13 judgment-day rounds; fixed async-state defects (stale closures, un-gated saves, ungated finally, supersede-during-write, busy state)
     - Led to new project skill: `.claude/skills/react-async-state` (9 rules, published to main at d1187b7/b79d4a1)
   - **Listas de Precio screen** (light, ~206 lines):
     - Extends generic catalog descriptor with conditional `modo`, `id_lista_base`, `porcentaje` fields
     - Reuses existing table/form machinery
     - 2 judgment-day rounds; fixed inactive-list selectable-as-base + orphan-option rendering

### Deviations from Original Plan (All Documented)

1. **Single `ListaPrecioAlta` contract** (ADR-11) instead of split `AltaListaPrecio`/`EdicionListaPrecio` — `ServicioDeListasPrecio` extends generic `ServicioDeCatalogo<T, TListado, TAlta>`, which binds one `TAlta` to both create and edit. Documented in `Contratos.cs`.

2. **Margin suggestion folded into Slice 2** instead of separate PR — no dependency on precios; called by `ServicioDeArticulos`.

3. **Screens split into 2 independent PRs** (#5 articulos, #6 listas-precio) instead of one bundled PR — articulos is the heaviest, listas reuses generic machine.

4. **`GET /api/articulos/{id}/codigos-barra` added mid-slice** (Slice 5, by judgment-day demand) — barcode manager needed to hydrate persisted codes. Spec updated.

5. **`listas-precio-minimal` spec drift resolved** — removed never-designed derivada read-resolution clause; clarified mode-switch guard applies only to precios history (which derivada lists never have by design).

### New Project Skill

**`.claude/skills/react-async-state`** — 9 hard rules distilled from Slice 5 judgment-day rounds:

Skill is now the canonical checklist for judges on async-state submissions (pushed to main at d1187b7/b79d4a1, used as judges' reference from R6 of Slice 5 onward).
